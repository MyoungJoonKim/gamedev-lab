# GameDev Lab

Unity 프로젝트와 함께 사용하는 개인 게임 개발 학습 사이트입니다. 작은 기능을 구현하고 테스트·디버깅·측정한 과정을 GitHub 포트폴리오로 남깁니다.

## 다른 PC에서 브라우저만으로 사용

서버 배포 모드를 추가했습니다: **본인 GitHub 로그인 · 서버 SQLite 저장 · 관리형 격리 C# 채점**. 접속하는 PC에는 Node.js나 .NET을 설치하지 않아도 됩니다.

[서버 배포 안내](docs/hosting.md)를 따라 Render 등 관리형 호스팅에 배포하세요. 호스팅·영구 디스크·채점 API는 요금과 서비스 계정 설정이 필요하며, 현재 인터넷 서비스가 생성된 상태는 아닙니다. 실제 접속 주소는 배포 후 발급됩니다. 이 저장소에는 비밀 키를 넣지 않습니다.

## 사이트 실행

Node.js 24 이상에서 npm 패키지 설치 없이 실행합니다.

```sh
npm start
```

기본 주소는 로컬 컴퓨터의 포트 3000입니다. 다른 포트는 `PORT` 환경 변수로 지정합니다. 서버는 127.0.0.1에 바인딩합니다.

C# 자동 채점에는 공식 **.NET SDK 8 이상**이 필요합니다. 설치 후 `dotnet --version`으로 확인하세요. Windows/macOS에서는 공식 SDK 설치 프로그램을 사용할 수 있습니다. Linux x86_64 클라우드에서는 다음 스크립트가 SDK 8.0.427을 저장소 상위 `.tools/dotnet`에 설치하고 공식 SHA512를 확인합니다.

```sh
bash tooling/install-dotnet.sh
```

서버는 해당 경로 또는 시스템 PATH의 SDK를 사용합니다. 다른 SDK 경로는 `GAMEDEV_DOTNET_DIR`로 지정할 수 있습니다. Unity와 웹 서버는 각각 실행합니다.

## 사용 흐름

1. 대시보드 → 수준 진단: 6문항과 해설로 출발점 확인.
2. 문제 라이브러리: 8단계, 9개 문제를 검색·난이도 필터로 선택.
3. 포켓·슬롯 문제: C# 풀이 작성 → **C# 실행·채점** → 실제 컴파일과 테스트 결과 확인.
4. Unity 문제: 로컬 에디터에서 구현·Test Runner 실행 → Save Results → 사이트에 같은 풀이 원문을 붙이고 XML 가져오기. 웹에서 Unity 실행/MCP 연결을 제공하지는 않습니다.
5. 분석 노트: 재현·가설·근거·최소 수정·회귀 검증·성능·AI 도움 범위를 기록.
6. 풀이 기록하기: 당시 코드와 결과를 이력으로 보존.
7. 학습 기록: Markdown 미리보기·다운로드 → GitHub의 `solutions/<문제>/README.md` 등에 직접 저장.
8. 기기 변경·브라우저 데이터 삭제 전 JSON 백업. 복원은 이력 ID 중복을 제거하여 병합하고 동일 문제의 초안은 가져온 내용으로 갱신합니다.

**기본 로컬 모드**의 학습 기록은 브라우저 **localStorage**에 저장됩니다. 배포 모드에서는 서버 DB에 저장되고 미전송 변경만 브라우저에 임시 보관합니다. 로컬 모드는 서버나 GitHub에 자동 업로드하지 않으며 같은 사이트라도 브라우저·포트가 달라지면 저장소가 달라집니다. 문제별 피드백은 고정 학습 가이드이며 AI 자동 분석·실측 최적화 판정이 아닙니다. 외부 결과는 사용자 제공 증거로 구분하며 독립적으로 인증하지 않습니다. 코드를 바꾸면 이전 테스트 결과는 ‘재검증 필요’로 표시됩니다.

## Unity 프로젝트

Unity Hub에서 이 저장소 루트를 엽니다. 에디터 버전은 **2022.3.62f3**입니다. Unity MCP v10.0.0이 패키지로 등록되어 있지만 서버 연결 여부는 별도입니다. NGO는 현재 manifest에 없습니다. 본 작업에서는 기존 Assets·Packages·ProjectSettings를 수정하지 않았고 실제 Unity 에디터 테스트도 실행하지 않았습니다.

## 검증

```sh
npm run check
npm test
npm run test:hosted
# 선택: Python Playwright와 /usr/bin/chromium이 있고 서버가 실행 중일 때
python3 tests/browser_smoke.py
```

단위·통합 테스트는 보고서·백업 검증, 오래된 결과 무효화, Markdown과 실제 C# 정상/버그/컴파일 실패, 프로세스 시간 제한을 확인합니다. 브라우저 테스트는 진단·편집·채점·Unity XML·이력·다운로드·복원·반응형 화면을 확인합니다. 별도 번들 빌드는 필요 없습니다.

## 로컬 실행과 공개 서버의 차이

기본 로컬 모드는 본인 코드만 실행하는 개인 개발 도구입니다. 로컬 실행 API는 동일 Origin의 JSON만 받고 한 번에 한 풀이를 실행하며 시간·출력 크기를 제한합니다. **C# 코드의 파일·네트워크 접근을 격리하는 샌드박스는 아닙니다.** 인증·다중 사용자 격리가 없으므로 공개 채점 서버로 노출하지 마세요. Linux에서 검증했으며 다른 운영체제는 별도 확인이 필요합니다.

공개 서버에는 반드시 `APP_MODE=hosted`와 인증·영구 디스크·격리 채점 서비스를 설정해야 합니다. 프로덕션에서 로컬 모드로 시작하거나 격리 서비스 없이 실행하려 하면 시작을 거부합니다. [배포 문서](docs/hosting.md)에 계정과 설정 절차를 정리했습니다.
