# GameDev Lab

게임 개발에 필요한 C#·Unity 기본기를 다지고, **코드를 이해하고 문제의 원인을 찾아 해결하는 능력**을 기르기 위한 개인 학습 저장소입니다. 기능별 문제를 직접 풀고 테스트하면서, 학습한 내용과 풀이의 변화를 GitHub에 쌓아갑니다.

**[문제와 풀이 기록 보기 →](./solutions)**

## 이 저장소를 만든 목적

직접 작성한 코드뿐 아니라 다른 사람이 작성한 코드나 기존 프로젝트를 읽을 때도 실행 흐름을 설명하고, 잘못된 동작을 재현하며, 근거를 바탕으로 수정할 수 있는 개발자가 되는 것이 목표입니다.

이를 위해 작은 기능부터 조건·반환값·상태 변화를 확인하고, 이벤트·비동기 처리·네트워크 권한처럼 여러 실행 흐름이 연결되는 문제로 학습 범위를 넓혀갑니다. 구현 결과와 함께 어떤 문제를 다뤘고 어떻게 검증했는지 남겨, 이후의 복습과 성장 과정을 확인할 수 있도록 합니다.

학습 중에는 다음 질문을 반복해서 확인합니다.

- 이 코드는 어디에서 실행되고, 어떤 순서로 호출되는가?
- 어떤 조건에서 누가 값을 변경하고, 결과는 어디로 전달되는가?
- 예상한 동작과 실제 동작이 처음 달라지는 지점은 어디인가?
- 수정한 결과가 올바른지 어떤 테스트나 실행 결과로 확인할 수 있는가?

## 어떤 내용을 연습하는가

여러 게임 장르에 공통으로 등장하는 기능을 주제로 삼습니다. 같은 개념을 다른 상황에도 적용할 수 있도록 기능과 동작 조건을 중심으로 문제를 구성합니다.

| 학습 영역 | 다루는 기능과 확인할 내용 |
|---|---|
| C# 기본기와 상태 관리 | 아이템 수량 제한, 체력·연료·내구도 변경, 조건과 반환값, 경계값 처리 |
| 컬렉션과 자료구조 | 인벤토리 슬롯, 중복 제거, 대상 탐색, 요청 대기열, 실행 취소 |
| 시간과 실행 제어 | 쿨타임, 중복 요청 방지, 비동기 작업의 완료·실패·취소 |
| Unity 기능과 이벤트 | 상호작용 판정, 참조와 설정 확인, 이벤트 구독·해제, UI 갱신 |
| 분석과 디버깅 | 재현 조건 정리, 호출 흐름 추적, 상태 불일치의 원인 확인, 수정 후 재검증 |
| 성능과 멀티플레이 | 실행 빈도와 작업량 측정, 소유권·서버 권한, 요청 전달과 상태 동기화 |

## 어떻게 학습을 진행하는가

로컬 학습 사이트를 이용해 **문제 이해 → 구현 → 실행·검증 → 수정 → 기록**의 과정을 반복합니다.

1. **문제를 읽고 예상 동작을 정리합니다.** 입력값, 변경되는 상태, 반환값을 확인하고 정상 동작과 예외·경계 조건을 구분합니다.
2. **직접 코드를 작성합니다.** 필요한 상태와 자료구조를 선택하고, 각 조건과 처리 순서를 설명할 수 있도록 구현합니다.
3. **실제 실행 결과를 확인합니다.** 기초 C# 문제는 .NET으로 컴파일하고 테스트합니다. Unity 실습은 에디터에서 동작을 확인하고 필요한 테스트 결과를 연결합니다.
4. **실패한 원인을 추적하고 수정합니다.** 예상과 달라진 조건이나 상태를 확인한 뒤 코드를 고치고, 기존에 동작하던 경우도 다시 검증합니다.
5. **풀이를 저장하고 날짜별로 정리합니다.** 학습 사이트에 풀이 이력을 남기고, 게시할 내용을 확인해 Git 커밋으로 기록합니다.

### 하루 기초 3문제

학습을 꾸준히 이어가기 위해 기초 문제 3개를 하루 목표로 사용합니다. 현재 기초 자동채점 문제 12개에서 미완료·오래된 문제를 우선 배정하고, 모두 풀면 복습합니다.

날짜는 한국 시간을 기준으로 구분합니다. 오늘 할당된 문제의 실제 채점을 통과하면 완료로 집계하며, 같은 문제를 여러 번 통과해도 한 문제로 셉니다. 일일 학습 화면과 달력에서 날짜별 진행 상황과 할당량 달성 여부를 확인합니다.

## GitHub에는 어떻게 기록하는가

문제와 풀이 기록은 [`solutions/`](./solutions)에 모읍니다. 폴더명은 `01_집기_인벤토리_체력`처럼 **순번과 학습한 기능**으로 구성해, 어떤 기능을 연습했는지 먼저 살펴볼 수 있도록 합니다. 학습 날짜는 각 Markdown의 문제 항목에 표시합니다.

각 풀이 문서는 다음 두 부분으로 구성합니다.

- **문제:** 구현할 기능, 요구사항, 학습일
- **내 풀이 코드:** 해당 문제에 직접 작성한 코드

커밋은 학습 날짜별로 구분합니다. 같은 날짜에 같은 문제를 여러 번 저장했다면 그날 마지막으로 저장한 풀이를 사용합니다. 사이트에서 날짜별 커밋 제목과 본문을 자동 작성한 뒤, 내용을 검토·수정하고 선택한 날짜를 커밋·푸시합니다. 같은 날 추가 학습을 게시하면 기존 기능 폴더를 갱신하는 추가 커밋으로 남깁니다.

풀이 문서에서 문제와 구현 결과를 읽고, 커밋 이력에서 날짜별 학습 내용과 변경 사항을 따라갈 수 있도록 관리합니다. 실제 풀이 파일은 학습 기록을 게시할 때 추가됩니다.
