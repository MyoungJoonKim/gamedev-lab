# 간단한 커밋 규칙

```text
종류(범위): 변경 내용 한 줄

이유: 변경 이유
변경: 핵심 변경 내용
검증: 실행한 테스트와 결과 (미실행이면 이유)
```

종류는 `feat`, `fix`, `refactor`, `test`, `docs`, `perf`, `chore`를 사용합니다. 범위는 선택입니다. 한 커밋에는 한 가지 목적을 담고 제목은 짧은 한국어로 씁니다.

```text
fix(inventory): 가득 찬 포켓에서 집기를 거부하도록 수정

이유: 아이템이 5개일 때 6개까지 증가함
변경: 최대 수량 조건을 >에서 >=로 수정
검증: 정상·가득 참·100회 반복 테스트 3개 통과
```

로컬 저장소에서 한 번만 설정하면 `git commit`을 입력할 때 템플릿이 열립니다:

```sh
git config --local commit.template .gitmessage
```

`git commit -m`은 템플릿을 사용하지 않습니다. `.meta`는 Unity 에셋과 함께 커밋하고 `Library`, `Temp`, `Logs`, 비밀 키는 올리지 않습니다. 성능 커밋은 동일 조건의 측정값을 남기고, 미측정 결과를 개선 완료로 쓰지 않습니다.

## 학습 기록의 날짜별 커밋

사이트의 `학습 기록 → 일자별 커밋 자동 작성`은 한국 시간 기준으로 기록을 묶습니다. 같은 날짜·문제는 마지막 기록만 선택합니다. 날짜마다 별도 커밋을 만들며 summary와 description을 직접 수정한 뒤 선택한 날짜를 커밋·푸시할 수 있습니다.

```text
docs(learning): 2026-10-31 집기·인벤토리·체력 풀이 정리

이유: 2026-10-31 게임 기능 학습 내용을 일자별로 정리

변경:
- 각 문제와 당일 마지막 풀이 코드 작성

검증:
- 실제 실행한 테스트 결과 또는 미실행 사유
```

summary의 날짜와 description의 이유·변경·검증 항목을 유지합니다. 파일은 `solutions/01_집기_인벤토리_체력/01_집기.md`처럼 생성하고 기존 번호를 보존합니다. Markdown에는 문제·요구사항·학습일과 본인 풀이 코드만 들어갑니다. 풀이를 다시 저장해도 버튼을 누르기 전에는 업로드되지 않습니다.

동일 날짜에 추가한 내용은 같은 폴더의 추가 커밋으로 반영합니다. 이미 게시한 커밋을 amend하거나 force push하지 않습니다. 기록을 삭제해도 기존 Git 파일은 삭제하지 않습니다. 선택 날짜 외의 미업로드 커밋이나 직접 수정한 풀이 파일이 있으면 자동 업로드를 중단하므로 먼저 Git 상태를 확인합니다. 푸시 실패 시 이미 만들어진 로컬 커밋을 유지하며 재시도로 업로드할 수 있습니다.
